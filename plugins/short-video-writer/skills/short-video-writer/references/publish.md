# 发布文案

视频已经剪好了。文案的工作是两件事：**让人点进来**（标题、封面字、第一行描述），**让看完的人有话说、有东西拿**（描述正文、互动、资源）。

## 1. 读素材

- **SRT 字幕**：去掉序号和时间码，把碎行合并成句子。
- **口播稿/脚本**：只取口播部分；画面说明能告诉你观众**看到了什么**。
- 专有名词、工具名、人名核一遍，听写出来的字幕常有错。

## 2. 想清楚文案要补什么

复述口播是最浪费的写法——看完视频的人不需要再读一遍。先填这张表：

| 问题 | 例 |
|---|---|
| 视频的主张，一句话 | PDF 先转成 Markdown 再发给 AI |
| 视频里一闪而过、观众记不住的 | 工具名、出处、两个方法各在什么时候用 |
| 对观众最具体的好处，谁最需要 | 一点额外费用都不花；天天要处理文件的人最需要 |
| 看完想动手，还缺什么 | 链接、安装命令、步骤（只放允许放的平台） |
| 视频结尾的互动原话 | 你平时会直接把文件发给 AI 吗？ |

文案就是把第 2–4 行补给观众。第 3 行（具体好处）每个平台都要有。

素材里没有的链接、命令、数据，只写你确定真实存在的；拿不准就空着，交付时告诉用户。

## 3. 标题：给 3 个打法

每个主要平台的标题给 3 版，打法不同（见 `hooks.md` 的钩子类型），各标一句它赌什么：

- **搜索型**（小红书、B 站、YouTube）：标题里放观众会搜的词，"怎么 + 问题"、"工具名 + 用途"。
- **推荐型**（抖音、视频号）：标题靠情绪和好奇，常常直接用视频第一句口播。
- 标题和封面字分工：封面字更短（≤8 字左右），负责一眼的冲击；标题负责补充信息。两者不要一模一样。

## 4. 各平台

规格看 `platforms.md`，下面是各平台的写法重点：

- **视频号**：熟人圈里刷到，像跟朋友说一句建议。一整段，第一句就把问题说清楚（折叠前只露这一句）。
- **抖音**：刷得快，描述一眼扫完。短句分行，结尾一个好回答的问题。正文不出现站外引流的词，会被限流。
- **小红书**：带着问题来搜的。正文要能单独当一篇小笔记看，不看视频也有收获。用 emoji 小标题分块，自然铺进搜索词。附一句封面大字建议。
- **B 站**：爱较真、爱动手。简介是"抄作业区"：链接、命令、步骤写全，命令原样写。附分区和标签建议。
- **YouTube**：靠搜索进来。中英文各一套，英文版按英文观众的习惯重写（换成他们熟悉的工具名和说法），不要直译。描述前两行要能单独看懂。

用户没说发哪些平台，就问一句；不想答就默认写视频号、抖音、小红书三个。

## 5. 自检

```bash
check.py copy <社交平台文案.md>
```

查字数、话题数、分行、emoji、引流词、禁用句式。口吻对不对，对照账号档案里的范例再读一遍。

## 输出模板

字段名照抄（自检脚本靠它们定位）。只写用户要的平台，其余整节删掉。

```markdown
# 社交平台文案 — <视频主题>

> 视频：<文件名>（<时长>，<横屏/竖屏>）｜账号：<账号名>
> 主张：<一句话>｜互动口径：<视频结尾原话>

---

## 视频号

**短标题**

**描述**

---

## 抖音

**标题**（3 选 1）

1. …（赌：…）← 推荐
2. …
3. …

**描述**

---

## 小红书

**标题**（3 选 1）

1. …
2. …
3. …

**正文**

> 封面建议：…

---

## B 站

**标题**

**分区建议**：…

**标签**

**简介**

---

## YouTube

### 中文版

**标题**

**描述**

### English

**Title**

**Description**
```

交付时在对话里直接贴出用户最常改的一段（通常是视频号描述或抖音标题），并列出需要他拿主意的地方。

## 用户定稿之后

用户改完说定稿了，问他要不要把定稿和改动（初稿哪句改成了哪句、为什么）追加到他的账号档案"改稿记录"里。几次之后，档案会比任何规则都准。
