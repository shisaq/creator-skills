# 口播稿

## 1. 先定三件事

动笔前用一句话回答，写在交付物的最前面：

- **给谁看**：具体到一类人（"刚开始用 AI 的上班族"，比"职场人士"好用）
- **看完记住什么**：只能有一个主张。想说两件事，就拆成两条视频
- **看完做什么**：点赞收藏（干货）、评论（观点）、关注（系列）、去试一下（教程）

素材很多时（会议记录、长文、字幕），先挑出最有冲击力的 30%，其余全部舍掉。短视频死于"什么都讲一点"。

## 2. 选结构

| 结构 | 节奏（60 秒为例） | 适合 |
|---|---|---|
| **钩子-痛点-解法-结果** | 0–3s 钩子 / 3–15s 把痛说具体 / 15–45s 解法分 2–3 步 / 45–60s 结果 + 互动 | 教程、工具 |
| **钩子-观点-三个证据-落点** | 0–3s 反常识 / 3–10s 亮观点 / 10–50s 每个证据 10–13s / 50–60s 落到观众身上 | 观点 |
| **冲突-经过-转折-收获** | 0–5s 冲突现场 / 5–35s 经过 / 35–50s 转折 / 50–60s 我学到了什么 | 故事、案例 |
| **清单（N 个）** | 0–3s 承诺 N 个 / 每个 10–15s，最好的放最后 / 结尾互动 | 盘点、技巧 |
| **先看结果** | 0–5s 展示成品 / 5–50s 倒回来讲怎么做 / 50–60s 引导去试 | 演示 |

时长按中文正常语速 **每分钟 240–270 字** 估算。用户没说时长，就按 45–75 秒写（约 200–320 字）。

## 3. 写

1. **先写 3 个开头**（见 `hooks.md`）：每个包括第一句（≤15 字左右）和前 10 秒，标注钩子类型和它赌的指标。推荐一个。
2. **用推荐的开头写完整稿。** 一句一行，段落之间空一行。
3. **在稿子旁边标出运营要素**：情绪转折在哪一句、开环在哪里埋下、在哪里兑现、每段大概几秒。
4. **念稿检查**（`spoken.md`），**禁用检查**（`banned.md`），跑脚本：
   ```bash
   check.py script <文件>
   ```
5. **去 AI 味**（见 SKILL.md 最后一道工序），开头钩子不交给去 AI 味工具改。

## 4. 改稿（用户给了现成的稿子）

用户说"太书面了""改得能录""开头太平"时：
- 先指出原稿最大的 1–2 个问题（例如："开头 40 个字才说到重点""全程没有情绪起伏"），再给改稿。
- 保留原稿的事实、数据和作者的个人表达习惯，改结构、节奏、用词。
- 改动大的地方，在旁边用一句话说明为什么改，用户下次自己就知道了。

## 输出格式

```markdown
# 口播稿：<主题>

> 给谁看：…｜记住什么：…｜看完做什么：…
> 预计时长：约 N 秒（M 字）｜结构：…｜情绪线：…

## 开头三选一

**A｜<钩子类型>（赌：<指标>）**　← 推荐
<第一句>
<前 10 秒>

**B｜<钩子类型>（赌：<指标>）**
…

**C｜<钩子类型>（赌：<指标>）**
…

## 口播稿（用开头 A）

<一句一行，段落之间空一行>

## 运营标注

| 时间 | 内容 | 作用 |
|---|---|---|
| 0–3s | … | 钩子：… |
| 8s | … | 开环：埋下… |
| 25s | … | 情绪转折：… |
| 55s | … | 兑现开环 + 互动提问 |

## 需要你确认

- 素材里没有、我不确定的事实（没有就省略这一节）
```

用户只要"纯口播"或"TTS 稿"时，只交付口播正文（一句一行，段间空行），其余省略。
