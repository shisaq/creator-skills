# 切片 JSON 规范与选片指南

起草 `<视频名>_chapters.json` 前读这份文件。

## 结构

```json
{
  "mode": "short-video",
  "chapters": [
    {
      "title": "02_观点_新人最容易踩的三个坑",
      "start_time": "00:05:25",
      "end_time": "00:07:38",
      "type": "观点",
      "score": "A",
      "summary": "嘉宾用三个真实经历讲新人入行最常见的误区，开头一句就有钩子。"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 会变成文件名。格式 `序号_类型_一句话标题`，中文/字母/数字/下划线即可，别用 `/ : " ?`。标题要让人不看视频也知道讲什么。 |
| `start_time` / `end_time` | 是 | `HH:MM:SS`、`MM:SS` 或秒数。是**内容**的入出点，切的时候脚本会自动前加 2 秒、后加 5 秒余量，这里不要自己加。 |
| `type` | 建议 | 见下表。 |
| `score` | 建议 | `A` / `B` / `C`，会作为文件名前缀（`A_02_...mp4`），方便一眼分拣。 |
| `summary` | 建议 | 一句话卖点：为什么值得单独看。 |
| 其他字段 | 可选 | 任意自定义字段（如 `column` 栏目、`speaker`）会原样写进 manifest。 |

## 两种模式

**short-video（默认）**——挑出能独立发成短视频的片段。判断标准只有一个：「不看前后文，这段自己立得住吗？」
- 跳过纯内部的环节：等人、调试设备、点名、排期、分任务、念二维码。
- 1–4 分钟最常见；金句可以 15–40 秒；超过 4 分钟考虑拆开。
- 少而精：45 分钟的会通常 8–20 条。

**archive（用户要"按议程切""每个环节一段""内部回看"时）**——按议程/话题把会议完整切开，不追求每段都能发布。
- 相邻片段首尾相接，允许覆盖全片；`score` 可省略。
- 类型可以用议程名代替（如 `议题`、`讨论`、`决议`、`Q&A`）。

## 类型（short-video 模式）

| 类型 | 抓什么 | 常见时长 |
|---|---|---|
| `金句` | 一两句就能立住的话：鲜明观点、反常识、好记的说法 | 15–40s |
| `观点` | 一个完整的论证：立场 + 理由 | 30s–2min |
| `案例` | 客户故事、真实场景、前后对比 | 1–3min |
| `演示` | 能看到东西的操作演示、产品画面 | 30s–3min |
| `干货` | 离开这场会也有用的方法、步骤、技巧、清单 | 1–3min |
| `其他` | 想留但不属于以上的：公告、答疑、背景介绍 | — |

## 评分

| 分 | 含义 | 什么时候给 |
|---|---|---|
| `A` | 优先发 | 开头就有钩子，不需要上下文，讲得清楚，有信息量或情绪 |
| `B` | 可用 | 内容不错，但要剪掉啰嗦部分或补个字幕标题才好看 |
| `C` | 存档 | 有参考价值，单独发效果一般 |

A 要克制，**一般不超过总数的四分之一**——如果大部分都是 A，评分就失去了分拣的意义。

## 找准入出点

阅读版文字稿是 25 秒一段，只够定位大概位置。定好候选片段后，到 SRT 里搜开头和结尾附近的句子，把时间精确到句子边界：
- 入点：落在这段话第一句开始处，不要切在半句话里；如果前一句是"那接下来我们讲……"这类引子且有助于理解，可以包含进来。
- 出点：落在结论句说完之后，不要带上下一段的开头。
- 识别错字不影响选片，但会出现在 HANDOFF 的"术语订正"里。

## 案例与隐私

对外发布的片段，`title` 和 `summary` 里不写客户全名、个人手机号等，用行业或角色代替（"某制造业客户"）。
