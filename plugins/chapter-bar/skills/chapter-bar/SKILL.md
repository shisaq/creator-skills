# 章节进度条

一条讲解视频，观众最想知道两件事：**一共讲哪几块，现在讲到哪了。** 章节条就是回答这两件事的。原视频画面不动，章节条叠在上面。

你来负责理解内容、划分章节、决定样式；脚本负责逐帧渲染和合成。两种内置样式够用就直接用，不够就自己写（见 [references/custom.md](references/custom.md)）。

## 怎么运行

```bash
uv run "<skill目录>/scripts/chapters.py" <命令> ...      # 下文简写成 chapters.py
```

依赖和 ffmpeg 会自动安装，Mac 和 Windows 命令一样。第一次先跑 `chapters.py doctor`。没装 uv 的话，把安装命令告诉用户，让用户自己装：macOS 运行 `curl -LsSf https://astral.sh/uv/install.sh | sh`；Windows 在 PowerShell 里运行 `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`。

## 流程

### 1. 了解视频

```bash
chapters.py look "<视频>"                 # 缩略图（带时间戳）+ 画面主色 + 有没有同名字幕
chapters.py look "<视频>" --grid 30       # 某一秒带坐标网格的大图（需要知道画面元素在哪时用）
```

划分章节**最好的依据是说了什么**。`look` 会告诉你视频旁边有没有字幕：

- **有字幕（.srt）**：直接全部读一遍
- **没有字幕**：先在本地转写一份，再读

  ```bash
  uv run "<skill目录>/scripts/transcribe.py" "<视频>" --reading-copy
  ```

  转写会在视频旁边生成两个文件：
  - `<视频名>_转写_阅读版.md`：每 25 秒左右一段，**先读这个**，用来把握话题怎么转换
  - `<视频名>_转写.srt`：逐句时间戳，用来定每一章精确的开始时间

  第一次运行会下载约 240MB 语音模型（国内走 ModelScope；在海外就设置 `MEETING_CLIPPER_REGION=global`），下载前先告诉用户。之后不再下载，和 creator-skills 的其他插件共用这份模型。速度大约是视频时长的 1/20。转写出来的错别字不影响分章节，不用改；如果用户还想要一份干净的字幕，可以推荐 subtitle-toolkit 接着润色这份 srt
- **视频基本没人说话**（纯录屏配音乐、纯演示）：看缩略图，画面切换往往就是换了话题，再请用户用一句话说说这条视频分哪几块

**已经用 meeting-clipper 分过段的视频**（视频旁边有 `<视频名>_chapters.json`，`look` 会提示），不用重新分，直接转成方案：

```bash
chapters.py from-clipper "<视频名>_chapters.json" "<视频>"
```

转换完把章节名缩短成下面要求的样子（切片标题通常是一整句话），然后跳到第 3 步。注意这份文件最好是按议程切的 archive 模式：挑精彩片段的 short-video 模式中间有跳过的部分，不是连续的章节，命令会提醒你。

### 2. 划分章节

原则：

- **4–8 章。** 少于 3 章不值得做章节条，超过 10 章会很碎。时长 3 分钟以内的视频，3–4 章就够
- **每章至少 10 秒**，最好 30 秒以上。YouTube 章节也有这个要求
- **第一章从 0 秒开始。** 开场白可以单独算一章「开场」，也可以并进第一个话题
- **章节名 2–6 个字，用名词短语，格式统一。** 比如「调速度 / 男女换调 / 循环练习」，不要「我们来看看怎么调速度」。并列的章节用同样的语法结构
- **在话题真正切换的那一句开头分章**，不要卡在上一句的尾音上。用字幕时间戳找到那一句的开始时间，往前留 0.3 秒左右
- 章节名要让**没看过视频的人也能看懂**。不要用只有讲者自己懂的内部说法

把章节写进方案：

```bash
chapters.py init "<视频>"      # 在视频旁边生成 <视频名>_章节方案.json
```

```json
{
  "video": "教程.mp4",
  "style": { "accent": "#FFC43D", "dark": "#1E1A16", "sfx": true },
  "bar": { "style": "tabs", "position": "top", "announce": false },
  "chapters": [
    { "start": 0, "title": "开场" },
    { "start": 59, "title": "平台介绍" },
    { "start": 96, "title": "格子谱" }
  ],
  "output": { "mode": "burn" }
}
```

### 3. 定样式

| 选项 | 什么时候用 |
|---|---|
| `bar.style: "tabs"` | 默认。整条深色底，每一章的名字都写出来，当前章亮起并带进度。适合教程、录屏，信息密度高 |
| `bar.style: "line"` | 极简：一根细进度线，换章时浮出「02 调速度」小标签，3.5 秒后收起。适合 Vlog、画面本身很满或很美的视频 |
| `bar.style: "none"` + `custom` | 你自己写的样式 |
| `bar.announce: true` | 换章时在画面中间弹出大字章节卡。适合 10 分钟以上的长教程，帮观众分段。短视频别开，太吵 |
| `bar.position` | `top` / `bottom`，按下面的规则选 |

**位置**：
- 先看缩略图和网格图，找出画面里**不能挡的东西**：字幕、讲者的脸、软件里正在演示的区域、播放器控件
- 横屏默认放顶部。如果顶部正在演示重要内容（比如网页的地址栏、菜单），而底部有空，就放底部
- 竖屏会自动避开平台的界面遮挡（顶部留 6%，底部留 13%），一般不用调。确实要调就用 `bar.y` 指定像素位置

**颜色**（`look` 会告诉你画面主色）：
- 主色 `accent` 是进度条和当前章节的颜色。用视频里本来就有的强调色或品牌色，跟画面才协调。画面偏灰、偏素时，默认的暖黄 `#FFC43D` 就很好
- 主色要跟画面主色拉开对比：画面偏暖黄，就别再用黄
- 深色 `dark` 是底色。画面整体偏暖就用暖深灰（默认），偏冷就用 `#161A20` 这类冷深灰
- 一共就两种颜色，再加灰色，不要更多

**音效**：`style.sfx: true` 时，换章会有一声很轻的「嗖」。讲解视频建议保留；有背景音乐、追求安静质感的视频就关掉。

### 4. 检查

```bash
chapters.py check "<视频>"            # 校验方案，并试画每个元素（自定义样式的代码错误也会在这里暴露）
chapters.py still "<视频>" --at 65     # 出几帧成品效果图，几秒钟就好
```

**检查清单**（每张图都要看，看不了图就请用户看）：
1. 章节名能看清吗？想象在手机上看：横屏视频的字高不要低于画面高度的 2%
2. 当前在哪一章一眼能看出来吗？
3. 有没有挡住字幕、脸、演示区域、播放器按钮？
4. 颜色跟画面打架吗？太跳就换成画面里已有的颜色，或者调低饱和度
5. 章节名放不下时，会被收成只在当前章显示的胶囊。如果大部分章节都这样，就缩短章节名或者合并章节

### 5. 出片

```bash
chapters.py render "<视频>"                 # 按方案里的 output.mode 输出
chapters.py render "<视频>" --mode both
```

| mode | 产出 | 给谁 |
|---|---|---|
| `burn`（默认） | `<视频名>_章节版.mp4`，可以直接发布 | 所有人，剪映用户只能用这个 |
| `overlay` | `<视频名>_叠加层.mov`，ProRes 4444 带透明通道 | 用 Final Cut / Premiere / 达芬奇、还想在剪辑软件里继续调整的人。文件大，1080p 每分钟约 120MB |

另外还会输出两个文件：
- `<视频名>_检查图.jpg`：每章抽一帧拼成的图，拿它按检查清单再过一遍
- `<视频名>_YouTube章节.txt`：3 章以上时生成，可以直接贴进 YouTube 简介

改了方案再 render，只会重画改动过的部分。

## 自己写样式

两种内置样式都不合适（比如用户想要圆点、时间轴刻度、跟品牌一致的造型），就继承 `ChapterBase` 写一个类，放在视频旁边的 .py 文件里，在方案里这样引用：

```json
"bar": { "style": "none" },
"custom": [{ "file": "my_bar.py", "class": "MyBar", "position": "bottom" }]
```

写法、可用的工具函数和一个完整的例子见 [references/custom.md](references/custom.md)。写完先跑 `check`：代码有错会在这里报出来，并给出行号。

## 交付时跟用户说

- 成片路径和检查图路径
- 章节划分的理由，一句话就够，比如「按话题分成 6 章，开场单独一章」
- YouTube 章节文字可以直接复制
- 他可以怎么调：改章节名、换位置、换颜色、改成极简样式，跟你说一声就行
